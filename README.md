# 覚えKnight

忘却曲線をヒントに、学びを思い出すタイミングをつくる復習アプリ。
アイボリーと深緑を基調にした、レスポンシブなブラウザアプリです。

## 機能

- メールアドレス・パスワードによるログインと、アカウントごとのクラウド保存
- `hgf51805@gmail.com` 専用のマスター管理画面（利用者追加・メール変更・パスワード再設定・利用停止）
- 学びの登録・編集・削除、カテゴリー別の検索
- カテゴリー設定ページで追加・名前変更・未使用カテゴリーの削除（登録フォームと絞り込みに連動）
- 期限を迎えた学びの自動ポップアップ（常時有効・切り替え設定なし）
- 答えを隠して思い出す復習画面
- 覚え具合による次回タイミングの調整
- 復習スケジュールと復習回数の表示
- 任意のブラウザ通知

## ローカルで起動

Node.js 22以降を使用します。ログインAPIが必要なため、静的ファイルのみの配信では動作しません。

```sh
git clone https://github.com/hgf81805/fukuyu.git
cd fukuyu
npm ci
npm run dev
```

ブラウザで http://127.0.0.1:4318 を開きます。

サーバー権限・入力検証などのテスト:

```sh
npm test
```

## カテゴリー設定

ナビゲーションの「カテゴリー」、または学びの登録画面の「カテゴリーを設定する」から管理できます。
既存のカテゴリーと登録済みの学びは引き継がれます。名前変更は既存の学びにも反映されます。
学びを登録途中でカテゴリー設定に移動しても、戻ると入力内容を引き継げます。
使用中のカテゴリーや最後の1つは削除できません。データは復習内容と同じログインアカウントに保存されます。

## 復習のタイミング

初回は「1日後」「今すぐ」「3日後」から選択できます。
復習で「覚えていた」を選ぶと、前回からの間隔を1日・3日・7日・14日・30日の順で設定します。
30日のステップ以降は30日ごとです。「あいまい」は1日後、「もう一度」は10分後に設定します。
忘却曲線を参考にした目安で、個人に共通する最適間隔を保証するものではありません。

## データ・通知

- 学び・履歴・カテゴリーは、Supabaseの `knight_learning_data` に利用者ごとに保存します。
- ブラウザにはアカウントIDごとの作業用キャッシュを保存します。未同期の変更がある場合は同期状態を表示します。
- 別画面との同時更新を検出した場合は上書きせず、未保存データをダウンロードできる確認画面を表示します。
- 旧 `yohaku-data-v1` データは、ログイン後に「このブラウザの以前の学びを取り込む」を押した場合のみ取り込みます。元データは削除しません。
- ログアウト・アカウント切り替えでは画面のデータと管理者フォームをクリアします。
- 自動の復習ポップアップと操作結果の通知メッセージは、表示から1秒で閉じます。手動で開いた復習画面や入力フォームは自動で閉じません。
- ポップアップはアプリを開いて表示している間に動作します。期限を30秒間隔で確認し、再表示時にも確認します。自動で閉じた復習は未完了のまま残り、10分後から再通知の対象になります。
- アプリを閉じている間のバックグラウンド通知には対応していません。
- ブラウザ通知は対応環境で許可した場合に使用できます。
- フォントはGoogle Fontsを使用し、読み込めない場合はシステムフォントに切り替わります。

## レスポンシブ対応

PCはサイドバー、タブレットはコンパクトなナビゲーション、スマホは下部ナビゲーションを使用します。
スマホのセーフエリアや横向き表示に対応し、フォームは入力時の拡大を避ける文字サイズにしています。

## マスターと認証

- マスターは、本人確認済みの `hgf51805@gmail.com` と固定したSupabaseユーザーIDの両方で照合します。ブラウザから送られた管理者フラグは信用しません。
- **設定 → 利用者アカウントを管理** から利用者を追加・編集できます。パスワードは12〜128文字です。既存パスワードの閲覧や平文保存はしません。
- 初期の共通パスワードを使う場合は、マスターが各利用者の作成時に同じ値を設定できます。他の利用者のメールアドレスとパスワードを知るとそのアカウントへログインできるため、個別パスワードへの変更を推奨します。
- マスター自身は既存Supabase Authのパスワードでログインします。そのパスワードはこの変更では再設定していません。
- 別アプリの既存Auth利用者は自動登録せず、管理画面で認証情報を変更できません。既存メールと同じメールでの新規追加は失敗します。
- アクセストークン・更新トークンはHttpOnly・Secure・SameSite=LaxのCookieで保持します。ブラウザJavaScriptやlocalStorageには認証トークンを渡しません。
- `knight_accounts`・`knight_learning_data`・`knight_sessions` はRLSを有効化し、匿名・別利用者・失効済みのアプリセッションからのデータアクセスを拒否します。
- アカウント停止・パスワード再設定では、その利用者の覚えKnightセッションを失効させます。別アプリのセッションは操作しません。
- データAPIはメールアドレスやユーザーIDを受け取って切り替えず、検証済みセッションのユーザーIDを使います。
- Supabaseの公開可能キーのみをソースに含めています。service roleキーはEdge Functionsの組み込み環境変数からだけ使用します。
- Edge Functionsは公開ログインや独自のBearerトークン検証を行うため、ゲートウェイの `verify_jwt` はfalseです。管理処理は毎回Authでトークンを検証し、固定マスターID・確認済みメール・有効な専用セッションを照合します。

## ローカル画面検証

実際のアカウントを操作しないUIテスト用データで確認できます。

```sh
PORT=4319 KNIGHT_UI_FIXTURE=1 node scripts/dev-server.js
```

このモードはループバックにバインドしたローカル開発サーバーのみが読み込みます。本番APIには組み込みません。
